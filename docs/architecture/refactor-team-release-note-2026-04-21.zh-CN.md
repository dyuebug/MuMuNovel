```md
## Summary

This MR closes the current refactor track for MuMuNovel across backend route/service boundaries, frontend service modularization, chapter-page orchestration cleanup, floating-index layering, and background-task-center cleanup.

## What Changed

### Backend
- Consolidated chapter route boundaries into clearer compat/workflow/query layers
- Split and stabilized `chapter_draft`, `chapter_crud`, and regeneration read-side responsibilities
- Added backend handoff and staging documents

### Frontend
- Modularized the service layer around `core/httpClient.ts`, `modules/*`, `modularApi.ts`, and a thin `api.ts` compatibility facade
- Added service-facade validation and wired it into lint/build
- Extracted chapter-page orchestration helpers, entry components, floating-index hooks/utils/components
- Streamlined background task center by moving presentation/selector/state-helper logic out of the component
- Synced project guides to the new service-layer entry conventions

## Validation
- `cd frontend && npm run validate:services`
- `cd frontend && npx tsc -b --pretty false`
- `cd frontend && npm run build`
- `cd frontend && npm run lint -- --quiet`
- Targeted backend py_compile / pytest validations on chapter-related APIs

## Risks
- `Chapters` bundle size can still be optimized in follow-up work
- Some backend compat services remain as transitional debt, but the current risk is much lower than before

## Follow-ups
- Optional package-size and lazy-loading optimization for `Chapters`
- Optional gradual cleanup of backend compat layers once downstream behavior is fully stable
```
