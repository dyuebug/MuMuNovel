# Claude + Notion + Mintlify 融合设计提示词

## 目的

本文件用于配合项目根目录的 `DESIGN.md`，指导 Codex 或其他 AI 编码代理在不改动业务逻辑的前提下，为 MuMuNovel 做更稳定、可扩展的前端重构。

这里不再把 `DESIGN.md` 只当作“Claude 单风格模板”，而是把它视为：

1. 全局视觉基座
2. 颜色、字体、圆角、深浅表面与按钮风格的统一来源
3. `claude + notion + mintlify` 融合提示词里的底层 token 约束

## 结论先说

可以融合，而且非常适合 MuMuNovel。

更准确地说，不应该把三个风格“平均混合”，而应该采用下面这套规则：

- `Claude` 负责品牌情绪和 AI 产品气质
- `Notion` 负责工作区结构、信息密度和长文本友好度
- `Mintlify` 负责阅读体验、说明模块、设置页和文档感工具界面

这样做的好处是：

- 不会把页面做成“拼贴风”
- 每类页面都有主风格，不会失焦
- 仍然能共享同一套颜色、字体和组件节奏

## 风格分工

### 1. Claude：品牌气质层

适合承接：

- 登录页
- 首页
- 灵感模式
- 章节创作入口

核心特征：

- 温暖的 cream canvas，而不是纯白后台
- 更有文学感的标题层级和 editorial rhythm
- coral 主 CTA
- dark product surface / workbench surface
- “AI 创作伙伴”而不是“普通管理后台”

### 2. Notion：工作区结构层

适合承接：

- 项目列表
- 世界观页面
- 角色管理
- 组织管理

核心特征：

- 信息分区清晰
- 模块边界克制，不花哨
- 大量长文本阅读仍然舒服
- 更强的 workspace 感和知识管理感
- 列表、表单、侧边栏、内容区关系明确

### 3. Mintlify：阅读增强层

适合承接：

- 设置页
- 帮助页
- 提示词工坊
- 各类说明型页面

核心特征：

- 文档阅读体验强
- callout、section、说明卡片结构清楚
- 工具页里带一点 docs-like clarity
- 更适合参数解释、帮助文案、配置说明、示例区

## 推荐融合方式

不要三种风格平均混合，建议使用：

- 全局基座：`Claude 50%`
- 布局结构：`Notion 30%`
- 阅读优化：`Mintlify 20%`

也可以理解为：

- 所有页面都先继承 `DESIGN.md`
- 然后按页面类型切换“主风格”
- 另外两种风格只作为辅助特征，而不是抢主导权

## 页面映射矩阵

| 页面类型 | 主风格 | 辅助风格 | 使用原则 |
|-----|------|------|------|
| 登录页 / 首页 / 灵感模式 / 章节创作入口 | Claude | Notion + Mintlify | 以品牌情绪和创作氛围为主，结构保持清晰，说明区可带少量文档感 |
| 项目列表 / 世界观 / 角色管理 / 组织管理 | Notion | Claude + Mintlify | 以工作区秩序和长文本友好为主，用 Claude 做品牌点亮，用 Mintlify 优化说明块 |
| 设置页 / 帮助页 / 提示词工坊 / 说明型界面 | Mintlify | Notion + Claude | 以阅读和理解效率为主，保持工作区秩序，再用 Claude 做品牌温度和按钮强调 |

## 使用方式

1. 确认项目根目录存在 `DESIGN.md`
2. 把下面的融合版提示词直接发给 Codex
3. 每轮只改一个页面或一组同类页面
4. 每轮改完后，对照“页面映射矩阵”检查主风格是否明确

## 融合版总提示词

```text
请读取项目根目录的 DESIGN.md，并把它作为当前任务的全局视觉基座。

现在请重构 MuMuNovel 的 [目标页面路径]，仅修改视觉层和界面表达，不改变任何业务逻辑、接口调用、状态流转、路由行为、权限语义和表单校验语义。

项目上下文：
- 这是一个 AI 小说创作工作台，不是营销官网，也不是传统后台系统
- 产品关键词：灵感、创作、长文本、角色关系、章节精修、多模型协同、创作工作流
- 现有技术栈：React 18 + TypeScript + Ant Design

总体设计策略：
- 不要只模仿单一风格，请融合 Claude、Notion、Mintlify 三种气质
- 但不要平均混合，更不要做成视觉拼贴
- 必须先确定当前页面的主风格，再让另外两种风格作为辅助

三种风格的职责分工：
- Claude 负责品牌气质：温暖、编辑感、AI 创作产品感、cream canvas、coral CTA、dark product surface
- Notion 负责结构秩序：工作区感、清晰的信息分区、长文本友好、安静克制的内容容器
- Mintlify 负责阅读体验：说明区、帮助区、提示区、参数解释区、文档式 section 和 callout

页面级风格路由规则：
- 如果当前页面属于 登录页 / 首页 / 灵感模式 / 章节创作入口：
  主风格使用 Claude，辅以 Notion 的结构秩序和 Mintlify 的说明模块表达
- 如果当前页面属于 项目列表 / 世界观 / 角色管理 / 组织管理：
  主风格使用 Notion，辅以 Claude 的品牌温度和 Mintlify 的信息说明结构
- 如果当前页面属于 设置页 / 帮助页 / 提示词工坊 / 文档型页面：
  主风格使用 Mintlify，辅以 Notion 的工作区布局和 Claude 的强调色与标题气质

设计要求：
- 严格遵守 DESIGN.md 中的颜色、字体层级、圆角、卡片、按钮、输入框和深浅表面节奏
- 整站必须共享同一套颜色系统与组件基因，不能每页像不同产品
- 页面主背景优先使用 warm canvas / soft surface，而不是纯白或冷灰
- 标题层级要有文学感、编辑感和可读性，必要时使用 serif display，但正文与操作区保持清晰易读
- 主 CTA 优先使用 coral 系主色，不要退回冷蓝科技风
- 合理引入 dark workbench surface，用于承载 AI 能力、工作区摘要、功能预览或辅助面板
- 列表、侧边栏、面板、表单区、说明区之间要形成清晰层次，而不是整页一个平面
- 提示、帮助、参数说明、空状态和次级信息区要有 Mintlify 式的清楚分组和阅读节奏
- 项目管理类和知识管理类页面要带有 Notion 式的 workspace calmness，但不能变成普通文档工具
- 保留 MuMuNovel 的“智能小说创作助手”定位，让页面看起来像高质量 AI 创作产品，而不是通用 SaaS 后台

实现约束：
- 不要引入新的页面级状态管理方案
- 不要新增 ad hoc fetch 或修改服务层调用
- 不要破坏移动端布局
- 优先复用现有 Ant Design 组件，通过 token、样式和布局重组完成升级
- 如果需要新增少量样式辅助函数或常量，保持单一职责并放在当前页面就近位置
- 不要为了“像某个网站”而牺牲项目自身可用性

重构时请重点检查：
1. 当前页面的主风格是否明确
2. 标题、副标题、正文、注释、帮助文案是否层级清楚
3. hero、toolbar、sidebar、content panel、callout、empty state 是否属于同一视觉系统
4. 列表/卡片/表单/设置说明区是否具备长时间阅读和使用的舒适度
5. 暗色模式下是否仍然保有相同气质，而不是退化成默认 dark theme

输出要求：
- 直接修改代码，不要只给设计建议
- 完成后说明该页面以哪一种风格为主，另外两种风格分别承担什么辅助作用
- 标出你做了哪些关键视觉决策
```

## 按页面类型调用的短提示词

### 1. 登录页 / 首页 / 灵感模式 / 章节创作入口

```text
请读取 DESIGN.md，并以 Claude 为主风格、Notion 为结构辅助、Mintlify 为说明辅助，重构 [目标页面路径]。

重点目标：
- 做出温暖、编辑感强的 AI 创作产品气质
- 保持结构清楚，不要失去工作区秩序
- 帮助文字、卖点和说明区要有良好的阅读节奏
```

### 2. 项目列表 / 世界观 / 角色管理 / 组织管理

```text
请读取 DESIGN.md，并以 Notion 为主风格、Claude 为品牌辅助、Mintlify 为阅读辅助，重构 [目标页面路径]。

重点目标：
- 强化工作区感、信息分区和长文本友好性
- 用 Claude 的颜色和标题气质提升品牌识别
- 用 Mintlify 的说明模块优化次级信息、空状态和帮助区
```

### 3. 设置页 / 帮助页 / 提示词工坊 / 文档型页面

```text
请读取 DESIGN.md，并以 Mintlify 为主风格、Notion 为布局辅助、Claude 为品牌辅助，重构 [目标页面路径]。

重点目标：
- 强化阅读效率、文档感和配置理解成本控制
- 保持像工作区而不是像博客
- 用 Claude 的温暖色彩和标题气质避免页面过冷、过硬
```

## 二轮收紧提示词

如果一轮改完后你还想继续收紧风格一致性，可以追加：

```text
在保持当前业务逻辑不变的前提下，继续收紧视觉系统一致性。

重点检查：
- 当前页面是否真的体现了设定好的主风格，而不是三种风格混在一起
- 是否仍存在不符合 DESIGN.md 的冷色按钮、默认阴影、过于通用的字体或不统一的圆角
- Claude 的 dark surface 是否足够像创作工作台，而不只是普通深色卡片
- Notion 式的结构秩序是否真实提升了长文本可读性和模块清晰度
- Mintlify 式的说明区是否真的帮助理解，而不是只增加装饰
- 移动端是否仍保留完整信息架构和良好可读性

如果发现冲突，请优先保证：
1. MuMuNovel 的可用性
2. 页面主风格明确
3. DESIGN.md 的全局一致性
```

## 落地建议

- 第一轮优先：`Login.tsx`、`ProjectList.tsx`、`BookshelfPage.tsx`
- 第二轮优先：`Inspiration.tsx`、`ProjectDetail.tsx`
- 第三轮优先：`Settings.tsx`、`PromptTemplates.tsx`
- 第四轮再扩到：`WorldSetting.tsx`、`Characters.tsx`、`Organizations.tsx`

## 最重要的约束

- `DESIGN.md` 仍然是视觉基线，不要把三风格融合做成三套 token 混战
- 每个页面只能有一个主风格
- 另外两种风格只能做辅助，不要抢戏
- 风格融合的目标是“统一而有层次”，不是“每块都不一样”
