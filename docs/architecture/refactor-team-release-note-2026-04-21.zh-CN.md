# 重构团队发布说明 / MR 备注（2026-04-21）

## 1. 说明

本文用于团队内同步本轮重构的范围、重点和评审关注点，适合附在 MR、发布说明或内部交接消息中使用。

## 2. 本次变更范围

本轮主要涉及两部分：

- 后端章节相关 API 边界整理
- 前端服务层模块化与章节页面编排拆分

同时补充了校验与交接文档：

- 服务层兼容门面校验
- 前端可见文本编码校验
- 架构说明与阶段性交付文档

## 3. 评审重点

建议评审时重点看以下内容：

### 3.1 后端

- 路由层是否只保留 request boundary、参数解析和 delegation
- draft / CRUD / regeneration / batch generation 的职责是否清晰
- 是否保持既有接口行为与兼容性

### 3.2 前端

- `services/api.ts` 是否仍只承担兼容门面职责
- `modularApi.ts` 是否保持统一命名导出约定
- `Chapters.tsx` 是否只保留页面编排，复杂逻辑是否已外移
- 新增校验脚本是否被正确接入构建链

## 4. 风险提示

本轮变更虽然以重构为主，但仍需关注以下风险：

- 章节链路属于高频页面，任何状态收敛失误都可能影响编辑、批量生成、导出等交互
- 路由兼容层若边界不稳，容易导致前端请求表现变化
- 历史文档中的编码污染仍未完全清理，不应把 `--include-docs` 结果直接作为当前 CI 阻断条件

## 5. 推荐验收命令

```bash
# 前端
cd frontend
npm run build

# 后端编码体检（默认代码目录）
python backend/tools/check_text_encoding_health.py

# 如需检查历史文档
python backend/tools/check_text_encoding_health.py --include-docs
```

## 6. 回滚与隔离建议

如果上线或联调阶段出现异常，优先按以下思路排查：

1. 先确认是否为结构重构导致的调用路径变化
2. 再确认是否为章节页面内部状态同步偏移
3. 最后确认是否为历史乱码或本地编码保存问题

如果必须局部回退，建议优先按模块或页面边界回退，不要把服务层、章节页和文档改动混在一起处理。

## 7. 结论

本轮变更适合作为阶段性交付合入，但建议：

- 继续保持分批、小步、可验证的推进方式
- 先收口文档乱码与编码治理，再继续扩大重构范围
- 后续每轮重构都同步更新交付文档，避免信息断层
