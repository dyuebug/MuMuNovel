## 1. 验证目标

R0.2 的目标不是证明某个 mock、单元测试或静态 workflow 合同可用，而是在本地真实启动
PostgreSQL 与 Rust runtime，并让现有 Playwright auth/background-task smoke 穿过完整生产所有权链：

```text
PostgreSQL 18-alpine
  -> Rust migration-executor
  -> Rust release-readiness-preflight
  -> cargo build --locked
  -> Rust server
  -> /readyz
  -> /releasez
  -> Playwright auth.spec.ts
  -> Playwright background-task-pages.spec.ts
  -> Rust lifecycle cleanup
  -> PostgreSQL cleanup
  -> local-r02-success.json
```

可重复执行入口：

```powershell
.trellis/tasks/07-12-rust-production-ci-e2e/validation/run-local-r02-real-e2e.ps1
```

该脚本使用唯一 PostgreSQL 容器名和可配置端口，将每次运行写入独立 evidence 目录，
并在 `finally` 中清理 Rust 进程和 PostgreSQL 容器。只有验证与清理全部完成后，才允许
写入 `local-r02-success.json`。

## 4. 失败轮次与根因闭环

失败证据保留，不删除、不覆盖。它们证明 harness 能失败关闭，也记录了真实问题如何收敛。

| Evidence 目录 | 结果 | 发现 |
|---|---:|---|
| `r02-local-real-e2e-20260713` | 4/14 | OAuth callback 在 React StrictMode 下永久 loading；后台任务 E2E 使用已删除的 Sponsor 路由跳板 |
| `r02-local-real-e2e-20260713-rerun1` | 13/14 | 首次 OAuth 登录断言仍依赖旧文案“当前账号：” |
| `r02-local-real-e2e-20260713-rerun2` | 预检失败 | 本机端口 `8005` 已被未知进程占用；harness 正确拒绝启动，未终止未知进程 |
| `r02-local-real-e2e-20260713-rerun3` | 13/14 | 用户名多处出现，非精确 locator 触发 Playwright strict-mode violation |
| `r02-local-real-e2e-20260713-final` | 14/14 | 业务链通过，但发现 success manifest 写入早于 cleanup，不能作为最终权威证据 |
| `r02-local-real-e2e-20260713-final2` | 14/14 | 验证、cleanup、success manifest 顺序全部闭环，作为权威证据 |

### 4.1 AuthCallback StrictMode 生命周期

根因是开发态 React StrictMode 会执行 effect setup → cleanup → setup 重放。旧实现 cleanup 后将
`mountedRef.current` 置为 `false`，第二次 setup 没有恢复为 `true`，OAuth callback 完成后被
`isRequestActive()` 当作失效请求，页面永久停留在“正在处理登录”。

修复合同：每次 effect setup 都必须执行：

```tsx
mountedRef.current = true;
```

真实 unmount 时 cleanup 仍将其设为 `false` 并推进 request id，继续拒绝迟到响应。

### 4.2 后台任务 E2E 路由漂移

旧 helper 先进入 `/project/:projectId/sponsor`，再查找目标导航链接；但 Sponsor 已不在
`AppRouter.tsx` 的项目子路由表中。测试失败来自历史导航跳板，而不是后台任务业务页面。

修复后直接访问当前已注册目标路由，并继续断言 URL 与真实任务请求：

```tsx
await page.goto(`/project/${projectId}/${subPath}`);
await expect(page).toHaveURL(
  new RegExp(`/project/${projectId}/${subPath}$`),
);
```

该调整没有降低真实链路强度，只移除了对已删除路由和易变导航布局的隐式依赖。

### 4.3 Playwright 可访问文案合同

首次登录页面当前可访问文本为“当前账号”，且用户名可能同时出现在标题、账号摘要和默认密码中。
断言改为 `exact: true`，使测试绑定当前可访问 UI 合同，并避免多个匹配导致 strict-mode violation。
