## 2. 已证明的问题

当前 Rust 认证已经使用 canonical Argon2id verifier。真实 PostgreSQL 18 + Rust migration +
Rust server 链路证明，生成的 PHC 字符串长度大于 64，无法写入：

```sql
user_passwords.password_hash VARCHAR(64) NOT NULL
```

失败路径为：

```text
AuthService::ensure_local_admin()
  -> Rust password_hash_service 生成 Argon2 PHC verifier
  -> 写入 user_passwords.password_hash
  -> PostgreSQL 拒绝长度大于 64 的值
  -> 本地登录链路返回 HTTP 500
```

Rust `/readyz` 和 `release-readiness-preflight` 已能只读诊断该容量问题，但诊断不能替代
Schema 修复，也不能使 R0.1、R0.2、R0.3 或 G0 通过。

---

## 3. 推荐决策

推荐批准以下最小变更：

```sql
ALTER TABLE user_passwords
ALTER COLUMN password_hash TYPE TEXT;

COMMENT ON COLUMN user_passwords.password_hash
IS '密码校验值（Argon2 PHC 或兼容的 legacy SHA256）';
```

目标类型选择 `TEXT`，而不是 `VARCHAR(128)` 或 `VARCHAR(255)`：

- password verifier 是密码算法产生的不透明字符串；
- 长度由算法、编码和参数决定，不属于业务字段约束；
- 再次猜测固定上限只会把当前兼容问题推迟到下一种 verifier；
- PostgreSQL `TEXT` 与当前 SeaORM `String` 映射兼容，不要求修改认证领域模型类型。

## 6. 数据兼容合同

### 6.1 Upgrade

`VARCHAR(64) -> TEXT` 必须满足：

- 现有 64 字符 legacy SHA-256 verifier 原样保留；
- `NOT NULL` 约束保持不变；
- 不修改 `user_id`、`username`、时间字段或索引；
- migration 在 revision 事务内原子执行；
- 成功后 Alembic head 才更新到新 revision；
- 失败时保持旧 head，Rust server 不进入 release-ready 状态。

### 6.2 Legacy verifier

升级后首次正确密码登录：

```text
读取 legacy SHA-256
→ Rust 验证成功
→ 生成 canonical Argon2id verifier
→ 写回同一 password_hash TEXT 字段
→ 后续登录使用 Argon2 验证
```

错误密码不得升级 verifier，也不得修改 `updated_at`。

### 6.3 Downgrade

推荐回滚方式是回滚应用代码但保留 `TEXT` Schema。当前 SeaORM `String` 可以继续读取
PostgreSQL `TEXT`，因此应用回滚不要求 Schema 降级。

新 revision 必须登记以下保护性 downgrade SQL，作为 executable catalog/source-map 完整性合同。
该 SQL 只允许在隔离 PostgreSQL 定向测试中通过测试 helper 执行；当前没有 production downgrade
命令，本授权也不允许新增或执行该命令。若未来单独批准真实 downgrade，必须先执行保护：

```sql
DO $$
BEGIN
    IF EXISTS (
        SELECT 1
        FROM user_passwords
        WHERE length(password_hash) > 64
    ) THEN
        RAISE EXCEPTION
            'cannot downgrade password_hash to VARCHAR(64): long verifier exists';
    END IF;
END
$$;
```

仅在所有值长度均不超过 64 时，才允许显式转换回 `VARCHAR(64)`。任何情况下都不得截断数据。

## 8. 验收矩阵

### 8.1 Schema

- 空库 migration 后字段为 PostgreSQL `text`；
- `is_nullable=NO`；
- old-head 数据库升级后字段为 `text`；
- legacy SHA-256 值逐字节不变；
- live head、Rust catalog head 和 frozen source-map head 一致；
- revision graph 保持单头、无分叉、无循环。

### 8.2 Auth

- 本地管理员首次创建成功；
- 新 verifier 是可解析的 canonical Argon2id PHC；
- verifier 长度大于 64 且完整落库；
- 正确 legacy 密码登录后自动升级；
- 错误 legacy 密码不升级、不修改时间戳；
- 修改密码和管理员创建用户使用相同 Rust hash owner。

### 8.3 Migration safety

- upgrade 在单 revision 事务内执行；
- 任一步失败时不推进 head；
- 隔离 PostgreSQL 定向测试通过测试 helper 执行 downgrade contract；
- downgrade guard 遇到长 verifier 明确失败；
- guard 失败后字段和值均不改变；
- production `migration-executor` 继续保持 upgrade-only，不新增 downgrade CLI；
- migration 日志和 artifact 不输出密码或 verifier 内容。

## 9. 失败处理

| 失败点 | 行为 |
|---|---|
| Revision graph 不健康 | 停止，不启动 migration executor |
| Upgrade SQL 失败 | 回滚 revision 事务，保持旧 head |
| 字段仍为 VARCHAR(64) | `/readyz` 和 preflight 保持 No-Go |
| Legacy verifier 发生变化 | 视为数据损坏，停止 R0.2 |
| Auth 返回 500 | 保存 PostgreSQL/Rust/Playwright 诊断，不回退 Python runtime |
| Downgrade 检测到长 verifier | 明确失败，保留 TEXT 和全部数据 |
| GitHub Runner 无真实证据 | R0.3 未完成，G0 保持 No-Go |
