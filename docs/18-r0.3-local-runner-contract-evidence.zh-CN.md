## 2. 单一执行链

workflow 继续由 `.github/workflows/e2e-smoke.yml` 单独拥有，没有创建第二套 CI 或证据 owner：

```text
PostgreSQL 18 ready
  -> Rust migration-executor
  -> Rust release-readiness-preflight
  -> cargo build --locked
  -> resolve binary absolute path + SHA-256
  -> start exact binary and save PID
  -> verify /proc/<pid>/exe path + SHA-256
  -> /readyz
  -> /releasez
  -> Playwright auth + background-task smoke
  -> re-verify PID identity
  -> TERM/KILL lifecycle cleanup
  -> success or failure manifest
  -> always upload e2e-diagnostics
```

Node 与 Rust 版本合同保持为 GitHub Runner Node 20、Rust 1.88；server 由构建后的 binary 直接启动，
不使用后台 `cargo run` wrapper。

## 3. Binary Identity 与 PID 安全合同

### 3.1 启动证据

启动步骤新增以下证据：

- `rust-backend-binary-path.txt`：`realpath` 后的绝对路径；
- `rust-backend-binary-sha256.txt`：构建产物 SHA-256；
- `rust-backend.pid`：真实 server PID；
- `rust-backend-identity.json`：期望/观察路径、期望/观察 SHA-256、PID 和身份状态。

server 启动后立即读取 `/proc/<pid>/exe`。路径或 SHA-256 任一不一致，workflow 失败关闭，不进入
readiness 和 Playwright。

### 3.2 cleanup 前复核

cleanup 不再把 PID 文件视为充分授权。发送信号前必须再次验证：

1. PID 是非空纯数字；
2. 期望 binary 路径和 SHA-256 文件存在；
3. PID 仍存在；
4. `/proc/<pid>/exe` 可读取；
5. 实际路径和 SHA-256 与启动证据一致。

任一身份条件失败，写入 `cleanup_status=signal_refused` 并返回非零；不得对该 PID 发送 `TERM`
或 `KILL`。这避免 GitHub Runner 上 PID 重用导致误杀未知进程。

## 4. Artifact 合同

统一的 `e2e-diagnostics` 现在可包含：

- migration stdout、stderr、退出码；
- release preflight stdout、stderr、退出码；
- `/readyz`、`/releasez` 响应和 HTTP 状态；
- Rust backend 日志、PID、binary 路径/SHA-256、identity JSON；
- Playwright 完整日志和原始退出码；
- lifecycle JSON；
- `runner-success.json` 或 `runner-failure.json`。

`rust-readiness-diagnostics` 使用 `if: always()`，成功与失败路径都会上传。成功 manifest 只在
cleanup 成功后生成，并绑定 `GITHUB_SHA`、`GITHUB_RUN_ID`、`GITHUB_RUN_ATTEMPT`、binary 路径和
SHA-256。失败路径生成结构化 `runner-failure.json`，Playwright HTML report 继续仅在失败时上传。

## 6. Linux 等价验证

本地证据目录从 YAML 原样提取全部 `run` 块，在 Debian Linux 容器执行 `bash -n`，结果：

```text
BASH_SYNTAX=PASS
```

cleanup harness 覆盖四个关键分支：

| 场景 | 预期 | 结果 |
|---|---|---|
| binary identity 匹配 | 发送 TERM，记录 `terminated` | PASS，exit 0 |
| binary identity 不匹配 | 拒绝信号，目标进程仍存活 | PASS，exit 1 |
| PID 非法 | 拒绝信号 | PASS，exit 1 |
| PID 已退出 | 记录 `already_exited`，失败关闭 | PASS，exit 1 |

该验证证明 shell 和安全分支在 Linux 用户态成立，但仍不替代 GitHub-hosted Runner。
