# MuMuAINovel 架构优化方案 - 基于《写书方法论》

> 基于实战方法论的深度架构重构与功能扩展提案

---

## 一、核心洞察提取

### 方法论关键发现

1. **平台差异化策略**
   - 番茄：同人文，日阅读人数计费，全勤600-800元
   - 飞卢：练手平台，快速迭代
   - 起点：成熟后进入，门槛较高

2. **风格学习机制**
   - 下载热门小说 → AI提炼风格 → 存储风格库 → 应用到创作

3. **影视融合规划**
   - 港综：无间道、追龙、古惑仔等经典IP
   - 时代选择：80年代后（影视资源丰富）

4. **深度研究资料生成**
   - 使用Google深度研究生成时代背景
   - 经济、军火、黑道、产业等垂直领域知识

5. **多AI协同工作流**
   - Gemini：深度研究、资料生成
   - Claude：风格提炼、逻辑推理
   - Grok：联网搜索、交叉验证

6. **交叉验证原则**
   - 至少2-3个独立信源
   - 冲突信息必须标注
   - 禁止单一来源依赖

7. **收益追踪需求**
   - 日阅读人数监控
   - 全勤奖励计算
   - 平台数据对接

## 二、架构优化提案

### 2.1 平台适配层（新增）

**模块名称**: `PlatformAdapter`

**核心功能**:
- 多平台配置管理（番茄/飞卢/起点/七猫等）
- 平台特性适配（字数要求、更新频率、爽点偏好）
- 收益数据追踪（日阅读、订阅、全勤）
- 平台规则引擎（敏感词过滤、题材限制）

**数据库设计**:
```sql
-- 平台配置表
CREATE TABLE platform_configs (
    id UUID PRIMARY KEY,
    user_id UUID NOT NULL,
    platform_name VARCHAR(50), -- 'tomato', 'feilu', 'qidian'
    platform_account VARCHAR(100),
    revenue_tracking BOOLEAN DEFAULT true,
    auto_publish BOOLEAN DEFAULT false,
    platform_rules JSONB, -- 平台特定规则
    created_at TIMESTAMP,
    updated_at TIMESTAMP
);

-- 收益追踪表
CREATE TABLE revenue_tracking (
    id UUID PRIMARY KEY,
    user_id UUID NOT NULL,
    project_id UUID NOT NULL,
    platform_name VARCHAR(50),
    date DATE NOT NULL,
    daily_readers INT DEFAULT 0,
    subscriptions INT DEFAULT 0,
    revenue DECIMAL(10,2) DEFAULT 0,
    full_attendance_bonus DECIMAL(10,2) DEFAULT 0,
    created_at TIMESTAMP
);
```

**API设计**:
```python
# backend/app/api/platform.py
@router.post("/platforms/config")
async def create_platform_config(...)

@router.get("/platforms/{platform_name}/revenue")
async def get_revenue_stats(...)

@router.post("/platforms/{platform_name}/publish")
async def publish_to_platform(...)
```

### 2.2 风格学习引擎（增强）

**模块名称**: `StyleLearningEngine`

**核心功能**:
- 热门小说爬取与解析
- AI风格提炼（句式、节奏、爽点分布）
- 风格库管理（存储、检索、应用）
- 风格迁移（将学习到的风格应用到创作）

**工作流程**:
```
1. 用户上传/爬取热门小说
2. AI分析：句式结构、对话风格、情节节奏、爽点密度
3. 生成风格特征向量（Embedding）
4. 存储到风格库（ChromaDB）
5. 创作时检索相似风格并应用
```

**数据库设计**:
```sql
-- 风格库表
CREATE TABLE style_library (
    id UUID PRIMARY KEY,
    user_id UUID NOT NULL,
    style_name VARCHAR(100),
    source_novel VARCHAR(200), -- 来源小说
    platform VARCHAR(50), -- 来源平台
    genre VARCHAR(50), -- 题材（港综、玄幻、都市）
    style_features JSONB, -- 风格特征
    embedding_id VARCHAR(100), -- ChromaDB向量ID
    popularity_score INT DEFAULT 0, -- 热度评分
    created_at TIMESTAMP
);

-- 风格应用记录
CREATE TABLE style_applications (
    id UUID PRIMARY KEY,
    project_id UUID NOT NULL,
    style_id UUID NOT NULL,
    application_scope VARCHAR(50), -- 'chapter', 'dialogue', 'description'
    effectiveness_score FLOAT, -- 应用效果评分
    created_at TIMESTAMP
);
```

**API设计**:
```python
# backend/app/api/style.py
@router.post("/styles/extract")
async def extract_style_from_novel(...)

@router.get("/styles/library")
async def get_style_library(...)

@router.post("/styles/{style_id}/apply")
async def apply_style_to_chapter(...)
```

### 2.3 影视融合规划器（新增）

**模块名称**: `MediaIntegrationPlanner`

**核心功能**:
- 影视IP库管理（电影、电视剧、动漫）
- 时间线规划（80年代、90年代等）
- 剧情融合建议（哪些情节可以融入）
- 角色关系映射（原著角色 → 小说角色）

**数据库设计**:
```sql
-- 影视IP库
CREATE TABLE media_ip_library (
    id UUID PRIMARY KEY,
    title VARCHAR(200),
    type VARCHAR(50), -- 'movie', 'tv_series', 'anime'
    genre VARCHAR(50), -- '港综', '仙侠', '都市'
    release_year INT,
    era VARCHAR(50), -- '80s', '90s', '2000s'
    key_characters JSONB, -- 关键角色
    key_plots JSONB, -- 关键情节
    popularity_score INT,
    created_at TIMESTAMP
);

-- 项目融合计划
CREATE TABLE project_media_integration (
    id UUID PRIMARY KEY,
    project_id UUID NOT NULL,
    media_ip_id UUID NOT NULL,
    integration_type VARCHAR(50), -- 'full', 'partial', 'reference'
    timeline_position VARCHAR(100), -- 在小说中的时间线位置
    plot_modifications JSONB, -- 剧情改动
    character_mappings JSONB, -- 角色映射
    created_at TIMESTAMP
);
```

**API设计**:
```python

@router.get("/media/library")
async def get_media_library(genre: str, era: str)
```

### 2.4 深度研究助手（新增）

**模块名称**: `DeepResearchAssistant`

**核心功能**:
- 时代背景研究（经济、政治、文化）
- 垂直领域知识生成（军火、黑道、产业）
- 多源信息交叉验证
- 知识图谱构建

**工作流程**:
```
1. 用户指定研究主题（如"80年代香港黑道"）
2. 调用Gemini深度研究API
3. 并行搜索多个信源（Wikipedia、学术论文、新闻报道）
4. 交叉验证信息一致性
5. 生成结构化知识库
6. 存储到向量数据库（ChromaDB）
```

**数据库设计**:
```sql
-- 研究主题表
CREATE TABLE research_topics (
    id UUID PRIMARY KEY,
    project_id UUID NOT NULL,
    topic_name VARCHAR(200),
    topic_type VARCHAR(50), -- 'era', 'industry', 'culture'
    research_scope JSONB, -- 研究范围
    status VARCHAR(50), -- 'pending', 'in_progress', 'completed'
    created_at TIMESTAMP
);

-- 研究结果表
CREATE TABLE research_results (
    id UUID PRIMARY KEY,
    topic_id UUID NOT NULL,
    source_type VARCHAR(50), -- 'gemini', 'wikipedia', 'academic'
    source_url TEXT,
    content TEXT,
    credibility_score FLOAT, -- 可信度评分
    embedding_id VARCHAR(100),
    created_at TIMESTAMP
);
```

**API设计**:
```python
# backend/app/api/research.py
@router.post("/research/topics")
async def create_research_topic(...)

@router.get("/research/topics/{topic_id}/results")
async def get_research_results(...)

@router.post("/research/topics/{topic_id}/verify")
async def cross_verify_information(...)
```

### 2.5 多AI协同编排器（增强）

**模块名称**: `MultiAIOrchestrator`

**核心功能**:
- 任务智能路由（根据任务类型选择最佳AI）
- 并行任务调度（多AI同时工作）
- 结果聚合与冲突解决
- 成本优化（优先使用性价比高的模型）

**路由策略**:
```python
TASK_ROUTING = {
    "style_extraction": "claude",  # Claude擅长风格分析
    "deep_research": "gemini",     # Gemini擅长深度研究
    "web_search": "grok",          # Grok擅长联网搜索
    "plot_generation": "openai",   # GPT-4擅长情节生成
    "dialogue_polish": "claude",   # Claude擅长对话润色
    "logic_check": "claude",       # Claude擅长逻辑推理
}
```

**API设计**:
```python
# backend/app/api/orchestrator.py
@router.post("/orchestrator/execute")

    task_type: str,
    task_params: dict,
    parallel: bool = False
)

@router.get("/orchestrator/status/{task_id}")
async def get_task_status(...)
```

## 七、风险评估

### 7.1 技术风险

**风险**: ChromaDB性能瓶颈
**缓解**: 使用分片策略，限制单个collection大小

**风险**: 多AI并发成本过高
**缓解**: 实施成本控制策略，优先使用免费/低价模型

**风险**: 平台API变更
**缓解**: 使用适配器模式，隔离平台差异

---

### 7.2 业务风险

**风险**: 风格提取准确性不足
**缓解**: 引入人工校验机制，逐步优化算法

**风险**: 敏感词过滤误杀
**缓解**: 提供白名单机制，支持人工审核

**风险**: 收益预测不准确
**缓解**: 明确标注为"参考值"，不作为承诺
